# Changelog

## Changes since v0.5.0

### Security

- Fixes eight vulnerabilities in the bundled WebAssembly runtime (RUSTSEC-2026-0320 to RUSTSEC-2026-0327) that let a tool, driver or hook crash or corrupt the host. Upgrade `mur`. No manifest or artifact changes needed. ([#240](https://github.com/murmur-nexus/murmur/pull/240))

### Features

- `mur run --roster` and `mur doctor` warn with `W-ROS-001` when more members can call a member than its `lifecycle.queue_depth` can hold. ([#281](https://github.com/murmur-nexus/murmur/pull/281))
- `mur trace show frm_…` names members by their roster name and lists every `call-member` call: who called whom, how it ended and how long it took. ([#269](https://github.com/murmur-nexus/murmur/pull/269))
- `mur stop` accepts a formation id from `mur ps` and stops every member of the formation. ([#264](https://github.com/murmur-nexus/murmur/pull/264))
- The entry member's `trace.retain` also cleans up ended formations in `~/.murmur/formations/`. Running formations are never removed. ([#263](https://github.com/murmur-nexus/murmur/pull/263))
- `mur new --roster <name>` scaffolds a working two-member formation that runs with `mur run --roster` as is. ([#249](https://github.com/murmur-nexus/murmur/pull/249))
- Formation members shut down by themselves when the formation ends, even if the launcher is killed. No capsule is left running. ([#248](https://github.com/murmur-nexus/murmur/pull/248))
- Formation members can only call the members `roster.yaml` allows. The runtime handles the credentials, which the agent never sees and which expire when the formation ends. ([#247](https://github.com/murmur-nexus/murmur/pull/247))
- `mur run --roster` starts every member, waits until each is ready, then starts the entry member. If one fails, the launch names it and stops the rest. ([#245](https://github.com/murmur-nexus/murmur/pull/245))
- `mur ps` groups formation members under a `FORMATION` column. `mur trace show frm_…` shows a formation after it has ended. ([#244](https://github.com/murmur-nexus/murmur/pull/244))
- Declare a formation in `roster.yaml`: its members, the entry member and which members may call which. Unsafe rosters are refused. ([#243](https://github.com/murmur-nexus/murmur/pull/243))
- `mur doctor` lists installed artifacts built for a WIT interface version this `mur` no longer supports, and the install that replaces each. ([#235](https://github.com/murmur-nexus/murmur/pull/235))
- The agent card lists the event types a capsule can stream, so clients know what to expect before they connect. ([#234](https://github.com/murmur-nexus/murmur/pull/234))

### Bug Fixes

- A formation member whose formation ends mid-task reports `formation_ended` and exits 0. A cancelled task's `out/result.txt` now says it was cancelled instead of showing an old answer. ([#284](https://github.com/murmur-nexus/murmur/pull/284))
- A task that hands out work with `call-member` or `delegate-task` waits for all answers, then continues once. Each round costs one turn of `inference.max_turns`. ([#282](https://github.com/murmur-nexus/murmur/pull/282))
- Error hints link to the docs site instead of source paths, some of which no longer existed. ([#279](https://github.com/murmur-nexus/murmur/pull/279))
- `mur` commands no longer panic when piped into `head` or another reader that stops early. ([#275](https://github.com/murmur-nexus/murmur/pull/275))
- Cancelling or stopping a task now also stops sub-capsules started by its plan steps. ([#274](https://github.com/murmur-nexus/murmur/pull/274))
- `mur install` works without `~/.murmur/config.yaml`, using the built-in `murmur-nexus/default-artifacts` source. ([#273](https://github.com/murmur-nexus/murmur/pull/273))
- When a shell command hits a resource limit, the model is told which limit and what to do about it. ([#272](https://github.com/murmur-nexus/murmur/pull/272))
- Failed model calls, such as a rejected API key, are recorded in the trace and shown by `mur trace show`. ([#271](https://github.com/murmur-nexus/murmur/pull/271))
- A long shell command on a `transport: process` capsule no longer blocks other tool calls. Up to 16 run at once. ([#268](https://github.com/murmur-nexus/murmur/pull/268))
- Warning links now open the right entry in the diagnostics reference. ([#266](https://github.com/murmur-nexus/murmur/pull/266))
- The model is now told that `delegate-task` returns as soon as the sub-capsule takes the task, not when it finishes. ([#252](https://github.com/murmur-nexus/murmur/pull/252))

### Other

- Breaking: On Linux, `cgroup_memory_bytes` now limits swap too. Raise it if a capsule needs more. `mur trace show` opens traces of sessions that ended abruptly. ([#288](https://github.com/murmur-nexus/murmur/pull/288))
- Breaking: A formation member can end its task with the built-in `end-without-answer` tool when a member it called gave no answer. `end-without-answer` is a reserved name. Conflicts fail with `E-CAP-013`. ([#285](https://github.com/murmur-nexus/murmur/pull/285))
- Breaking: `mur ps` reports pruned records in one line. Use `--verbose` for the details. Formation launches print the `W-SEC-013` warning once. ([#283](https://github.com/murmur-nexus/murmur/pull/283))
- Breaking: `mur run` and `mur deploy` no longer print door tokens. Get them with the new `mur token` command. ([#278](https://github.com/murmur-nexus/murmur/pull/278))
- Breaking: Turn numbers keep counting across a reopened or continued task instead of restarting at 0. `mur trace show --body --turn` refuses ambiguous turn numbers. Use the hash instead. ([#276](https://github.com/murmur-nexus/murmur/pull/276))
- Breaking: On Linux, `cgroup_pids_max` replaces `max_processes` for capsules that start subprocesses. Move any tighter limit there. This fixes `EAGAIN` failures in long sessions. ([#270](https://github.com/murmur-nexus/murmur/pull/270))
- Breaking: `inference.provider` and `trace.include_tool_output` are no longer read. Rename them to `inference.driver` and `trace.capture` (`content` or `meta`). ([#261](https://github.com/murmur-nexus/murmur/pull/261))
- Breaking: `delegate-task` results arrive in the task that started them, on every lifecycle. The `queue` and `sleep` setup is no longer needed. Cancelling a task stops its sub-capsules. ([#260](https://github.com/murmur-nexus/murmur/pull/260))
- Breaking: Formation members can hand work to each other with the built-in `call-member` tool. `call-member` is a reserved name. Conflicts fail with `E-CAP-013`. ([#251](https://github.com/murmur-nexus/murmur/pull/251))
- Breaking: Sub-capsules shut down when the capsule that started them ends, even if it is killed. ([#250](https://github.com/murmur-nexus/murmur/pull/250))
- Breaking: `mur-roost` counts already running capsules when it starts, so a restart cannot exceed `--max-live-capsules`. It needs an absolute `HOME`. ([#246](https://github.com/murmur-nexus/murmur/pull/246))
- Breaking: `MURMUR_FORMATION_ID` must be unset or a valid formation id, or `mur run` fails with `E-RUN-044`. Do not set it by hand. ([#242](https://github.com/murmur-nexus/murmur/pull/242))
- Breaking: Capsules refuse tasks from other capsules unless `murmur.yaml` declares `exports.peer_tasks.accept: true`. ([#241](https://github.com/murmur-nexus/murmur/pull/241))
- Breaking: `mur doctor` output wording changed from "formation" to "spawn closure". Update scripts that match it. ([#239](https://github.com/murmur-nexus/murmur/pull/239))
- Breaking: Clients see tool calls as the model writes them. Rebuild every driver: process drivers need `murmur:driver@0.3.0`, HTTP drivers `murmur:stream@0.1.0`. Older drivers fail with `E-RUN-029`. ([#237](https://github.com/murmur-nexus/murmur/pull/237), [#238](https://github.com/murmur-nexus/murmur/pull/238))
- Breaking: Tool calls missing a required input field are refused before the tool runs. Remove fields from `required` if the tool defaults them. ([#236](https://github.com/murmur-nexus/murmur/pull/236))
