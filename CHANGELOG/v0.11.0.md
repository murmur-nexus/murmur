# Changelog

## Changes since v0.10.0

### Features

- `mur install` checks the GitHub artifact attestation published beside each release asset. It refuses an artifact whose bytes do not match, warns when there is none, and records the signer in `murmur.lock`. `mur doctor` shows each installed artifact's attestation state. ([#409](https://github.com/murmur-nexus/murmur/pull/409))
- A `runtime: tool` artifact pins a per-platform download of a program it runs under `programs.<program>.download`. `mur install` fetches and checks it once, and a capsule that lists the program in `capabilities.shell.allow` runs that copy by name. `mur doctor` and the trace show which copy runs. ([#406](https://github.com/murmur-nexus/murmur/pull/406))
- Tool artifacts declare in a `programs:` block the libraries, fonts, CA bundle and `/etc` files each program needs, by name instead of host path. A capsule that pins the tool and grants the program in `capabilities.shell.allow` gets them read-only. `mur run --explain-scope` shows them. ([#399](https://github.com/murmur-nexus/murmur/pull/399))
- A formation member's tools, hooks, drivers and scripts that call another member leave a `member_request` line in the caller's trace. It names the component, the outcome, the member's task id and the duration. `mur trace show frm_<id>` joins it to the callee's task. ([#397](https://github.com/murmur-nexus/murmur/pull/397))

### Bug Fixes

- `mur trace show`, `mur trace steps`, `mur trace diff`, `mur trace report`, `mur eval show`, `mur eval diff` and `mur run --resume` find a session named by its full `ses_` id from any folder. An id found nowhere names every place searched. ([#403](https://github.com/murmur-nexus/murmur/pull/403))
- When a capsule command starts a server on a port that `capabilities.network.allow` names, its shell result ends with a line naming that port and the allow entry holding it. Before, only `Address already in use` showed. ([#400](https://github.com/murmur-nexus/murmur/pull/400))
- On AppArmor hosts, `mur doctor` and the `E-CAP-005` and `E-CAP-003` refusals say whether the `mur-sealed` profile is not loaded or does not cover the path `mur` runs from. Each gives the command that fixes it. The docs gain an Install mur page. ([#402](https://github.com/murmur-nexus/murmur/pull/402))

### Other

- Breaking: A capsule's WASM tools, drivers and hooks run in worker processes under the capsule's containment class. Every agent capsule needs the network namespace and cgroup scope a shell capsule needs. A host without them refuses with `E-CAP-005` or `E-RUN-012`, so run `mur doctor`. ([#414](https://github.com/murmur-nexus/murmur/pull/414))
- Breaking: A `transport: process` harness and every program it runs run under the capsule's containment class like a shell command. Rebuild each process driver against `murmur:driver@0.6.0`, grant its folders and hosts, and list its programs in `capabilities.shell.allow`. ([#413](https://github.com/murmur-nexus/murmur/pull/413))
- Breaking: Skills follow the Agent Skills standard. A skill folder holds a `SKILL.md` whose front block has `name` and `description`, and `metadata.version` for `mur build`. Skills holding the old `skill.md` are refused until you rebuild them. ([#412](https://github.com/murmur-nexus/murmur/pull/412))
- Breaking: Session records are hash-chained and sealed with a host key kept in `~/.murmur/keys`. `mur trace verify <session>` checks a record with the public key and names the first changed line. A `host_paths` entry covering `~/.murmur/keys` is refused. ([#408](https://github.com/murmur-nexus/murmur/pull/408))
- Breaking: `mur doctor --json` gives the verdict and every finding with its code. For a `transport: process` capsule, `mur doctor` checks that the harness is installed and logged in for this user. ([#405](https://github.com/murmur-nexus/murmur/pull/405))
- Breaking: `mur run --unconfined` and `containment: unconfined` in `~/.murmur/config.yaml` are refused when `mur` runs as root, including for `mur run --roster` members. Run `mur` as a normal user, or run the capsule contained. ([#404](https://github.com/murmur-nexus/murmur/pull/404))
- Breaking: `mur doctor` reports every finding that means `mur run` will refuse the capsule as an error, names the first one under its tally and exits 1. A CI step running `mur doctor` against such a host fails where it used to pass. ([#401](https://github.com/murmur-nexus/murmur/pull/401))
- `mur run` runs a capsule's WASM tools, drivers, hooks and a script capsule's own component in separate guest worker processes. The gateway key and the session records stay in a process that runs no WASM code. A worker that dies fails its task with `E-RUN-065`. ([#411](https://github.com/murmur-nexus/murmur/pull/411))
