# Changelog

## Changes since v0.4.0

### Security

- wasmtime moves to 48, which resolves RUSTSEC-2026-0313. ([#220](https://github.com/murmur-nexus/murmur/pull/220))

### Features

- Capsules with a `capabilities.install` grant can uninstall skills and tools they pulled at runtime with `manage.remove()`. Artifacts declared in `murmur.yaml`, `origin: operator` pins, hooks and drivers cannot be removed. ([#228](https://github.com/murmur-nexus/murmur/pull/228))
- `inference.tool_refresh` sets when an artifact installed mid-session reaches the model. `compaction`, the default, waits for the next compaction. `immediate` adds it on the next inference call, at the cost of one prompt-cache miss. ([#226](https://github.com/murmur-nexus/murmur/pull/226))
- Capsules can require an HTTP Bearer token on their A2A door with `network.authentication`. `mur run` prints the tokens, and only authenticated callers see the session id, tools and grants on the agent card. `mur run --bind`, `mur doctor --bind` and `mur deploy` warn with `W-SEC-032` when a capsule without it is reachable off loopback. ([#225](https://github.com/murmur-nexus/murmur/pull/225))
- `mur control` changes a running capsule within what its `control:` block allows: `inference.max_tokens` and the credentials behind an artifact's `gateway.api_key`. Injected secrets stay in memory and never reach the trace, the conversation record or the agent. ([#222](https://github.com/murmur-nexus/murmur/pull/222))
- On Linux, capsules with `capabilities.shell.allow`, `capabilities.spawn.allow` or a native tool start about 20 ms faster. Setting up their cgroup scope no longer adds a fixed wait. ([#216](https://github.com/murmur-nexus/murmur/pull/216))
- `mur install` compiles the WASM tools, drivers and hooks it installs, so the first `mur run` does not have to. With no arguments it compiles those already in the store. Skip it with `--no-precompile`. ([#214](https://github.com/murmur-nexus/murmur/pull/214))
- A warm `mur run` no longer re-checksums every compiled artifact in `~/.murmur/compiled`. Each is verified once, and again only after its file changes. ([#212](https://github.com/murmur-nexus/murmur/pull/212))
- A warm `mur run` reaches its first inference request sooner, because the token counter is prepared while artifacts load (300 ms to 228 ms for the Nexus coding capsule). ([#211](https://github.com/murmur-nexus/murmur/pull/211))
- Compiled copies that a `mur` upgrade leaves behind are removed after 30 days without use, and `mur doctor` names `~/.murmur/compiled` as a cache that is safe to delete. ([#210](https://github.com/murmur-nexus/murmur/pull/210))
- A warm `mur run` no longer decompresses WASM tools and hooks that are already compiled (131 ms to 115 ms for the Nexus coding capsule). ([#209](https://github.com/murmur-nexus/murmur/pull/209))
- `manage.pull()` shares the compiled cache with `mur run`, so pulling an already compiled version no longer recompiles it. ([#208](https://github.com/murmur-nexus/murmur/pull/208))
- `mur run` caches compiled WASM artifacts in an owner-only `~/.murmur/compiled`, which `mur doctor` reports. Launches after the first skip recompiling (5.1 s to 0.28 s for the Nexus coding capsule). ([#205](https://github.com/murmur-nexus/murmur/pull/205))

### Bug Fixes

- Hooks calling `run-inference` on a `transport: process` capsule get an error saying that transport does not support it. The old error asked for an `inference.driver.artifact` the manifest already declared. ([#230](https://github.com/murmur-nexus/murmur/pull/230))
- `mur deploy run` compiles WASM tools, drivers and hooks on the target host, so a fresh deploy launches as fast as a warm one. Skip it with `--no-precompile`. The new `mur precompile` compiles any `.mur.zip` for the machine it runs on. ([#219](https://github.com/murmur-nexus/murmur/pull/219))
- `transport: process` capsules no longer drop the output of `on-inference` hooks. It arrives as an `artifact` event before `completed`, as on `transport: http`. ([#218](https://github.com/murmur-nexus/murmur/pull/218))
- Extra A2A tasks accepted under `lifecycle.after_task: exit` or `task_acceptance: single` no longer vanish when the session ends. They end `rejected` and `mur trace show` lists them. Messages sent after the session stops taking work are also answered `rejected`. ([#217](https://github.com/murmur-nexus/murmur/pull/217))

### Other

- Breaking: Capsules can declare `inference.alternates` and switch driver while running with `mur control set inference.driver <name>`, or through the built-in `switch-driver` tool where `control.agent_settings` allows it. `switch-driver` is now a reserved name. Rename any artifact using it, or launch fails with `E-CAP-013`. ([#229](https://github.com/murmur-nexus/murmur/pull/229))
- Breaking: Skills and tools pinned with `origin: runtime` reach the model fenced as untrusted. The trace records their origin and trust, plus a new `artifact_pulled` line. Naming such a pin in `inference.system_prompt_artifact` fails with `E-RUN-043` until `mur install <name>@<version>` adopts it. ([#227](https://github.com/murmur-nexus/murmur/pull/227))
- Breaking: `manage.pull()` requires a `capabilities.install` block naming what a capsule may install (exact names, `prefix-*` or `*`). Capsules that pulled without one must add it. `mur-roost` refuses a child whose install grant is wider than its parent's. ([#224](https://github.com/murmur-nexus/murmur/pull/224))
- Breaking: `murmur.lock` entries record `origin: operator` or `origin: runtime`. Artifacts fetched through `manage.pull()` cannot be hooks or drivers or have a `gateway:`. `mur run` refuses them with `E-RUN-043` until `mur install <name>@<version>` adopts the pin. Older locks keep working. ([#223](https://github.com/murmur-nexus/murmur/pull/223))
- Breaking: The agent card at `/.well-known/agent-card.json` is now a standard A2A v1.0 AgentCard. The address moves to `supportedInterfaces`, Murmur's own fields move under `capabilities.extensions`, and `capabilities.cancellation` is removed. Update clients that read the old card. ([#221](https://github.com/murmur-nexus/murmur/pull/221))
- Breaking: A streamed task ends with exactly one final `status` frame, sent after its `on-task-end` hooks decide. Each reopen appears as a non-final `working` frame with a `reopen` number. Clients should read the answer from the last frame's `response`. ([#215](https://github.com/murmur-nexus/murmur/pull/215))
- Breaking: `mur run` exits non-zero and prints the real outcome, such as `failed` or `max_turns_reached`, when its task does not complete. `tasks/get` and delegation results report it as failed, and the trace adds a `task_failed` line. Scripts that treated these outcomes as success must handle the exit code. ([#206](https://github.com/murmur-nexus/murmur/pull/206))
- Breaking: The model never receives an empty task. A capsule with `task_acceptance: queue` and `after_task: exit` exits when its `--task` finishes instead of idling and prompting the model with nothing. A blank `--task` or A2A message fails. Capsules that ran from their system prompt alone must now get their instruction with `--task`. ([#204](https://github.com/murmur-nexus/murmur/pull/204))
- `mur install` and `mur run` verify artifact checksums about three times faster. `murmur.lock` and stored checksums are unchanged. ([#207](https://github.com/murmur-nexus/murmur/pull/207))
