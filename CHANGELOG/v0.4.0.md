# Changelog

## Changes since v0.3.0

### Features

- Canceling a task on a `transport: process` capsule now stops the harness. The runtime sends the driver's interrupt and kills the harness after ten seconds. The capsule stays usable for its next task. ([#197](https://github.com/murmur-nexus/murmur/pull/197))
- `transport: process` capsules stream text, reasoning, tool calls and one final status to watching clients, like HTTP capsules. Agent cards now carry a `capabilities.cancellation` flag. ([#196](https://github.com/murmur-nexus/murmur/pull/196))
- `transport: process` capsules keep their conversation across messages with `lifecycle.conversation: threaded`. `mur run --resume` continues it after a restart. A session the harness can no longer find fails instead of silently starting over. Start a new conversation under the same context id with `mur run --forget-session` or the `x-murmur-forget-session: true` header. ([#195](https://github.com/murmur-nexus/murmur/pull/195), [#201](https://github.com/murmur-nexus/murmur/pull/201))
- Process drivers can be built against the new `murmur:driver/process` interface and named in `inference.driver`. The runtime checks the driver's interface and its `capabilities.env.allow` grants at launch. ([#193](https://github.com/murmur-nexus/murmur/pull/193))
- Agent cards include a `serves` block listing the JSON-RPC methods and file planes (`exports.files`, `exports.peer_files`) a capsule serves. Clients can check support there instead of the version number. `capabilities.streaming` is now `false` under `lifecycle.task_acceptance: none`. ([#182](https://github.com/murmur-nexus/murmur/pull/182))

### Bug Fixes

- `mur run --json` no longer kills the capsule when the launching program stops reading its output. ([#190](https://github.com/murmur-nexus/murmur/pull/190))
- Event ids on `message/stream` and `stream/watch` now count up from 1 across the session on the standard `id:` line. Reconnecting with `Last-Event-ID` resumes right after the last frame received. `gap` frames appear only when frames were evicted or the id is from an earlier session. ([#189](https://github.com/murmur-nexus/murmur/pull/189))
- Streams that fall too far behind receive a `lagged` frame with the number of missed frames. `mur watch` prints it as a warning. ([#188](https://github.com/murmur-nexus/murmur/pull/188))
- Idle `stream/watch` connections get a `:heartbeat` line every 15 seconds, so clients can tell an idle capsule from a dropped connection. ([#180](https://github.com/murmur-nexus/murmur/pull/180))
- `artifact` stream frames and conversation records now say whether content is fenced as untrusted and what produced it. ([#179](https://github.com/murmur-nexus/murmur/pull/179))

### Other

- Breaking: A task reopened by an `on-task-end` hook now continues its own conversation. The rejected answer stays in context and the hook's feedback arrives as the next message. Reword feedback written to brief a fresh attempt. ([#203](https://github.com/murmur-nexus/murmur/pull/203))
- Breaking: `transport: process` capsules record the harness's token counts and respect `inference.max_session_tokens` and `spend.machine_tokens_per_day`. Rebuild process drivers against `murmur:driver/process@0.2.0`. ([#200](https://github.com/murmur-nexus/murmur/pull/200))
- Breaking: On `transport: process`, `on-tool-call` policy hooks and `capabilities.filesystem.read_only` now refuse tool calls instead of being ignored. Remove either declaration if you relied on the calls running. ([#199](https://github.com/murmur-nexus/murmur/pull/199))
- Breaking: `transport: process` capsules run their harness through the driver in `inference.driver.artifact`, which is now required. Manifests with only `inference.command` are refused, and Codex has no process transport until a Codex driver ships. The harness sees only `capabilities.env.allow` variables and is stopped after 600 seconds without output. ([#194](https://github.com/murmur-nexus/murmur/pull/194))
- Breaking: `upstream_auth:` replaces `inference_auth:`, which is refused for artifacts with a `gateway:`. Upgrade to murmur-driver-anthropic 0.7.0, murmur-driver-deepseek 0.5.0, murmur-driver-moonshotai 0.4.0 and murmur-driver-openai 0.6.0, and rename the block in your own artifacts. ([#192](https://github.com/murmur-nexus/murmur/pull/192))
- Breaking: Tools, hooks and drivers can call keyed APIs without holding the key through `gateway: {endpoint, api_key}` on their `artifacts:` entry. `inference.endpoint` and `inference.api_key` are removed, so move both onto the driver's entry. Gateways without a key need `keyless: true`. ([#191](https://github.com/murmur-nexus/murmur/pull/191))
- Breaking: Conversation messages read by hooks carry an `inserted-by` field marking compaction summaries and `seed-context` content. Hooks now use `murmur:hook@0.9.0`. Rebuild and reinstall all hooks. ([#187](https://github.com/murmur-nexus/murmur/pull/187))
- Breaking: `mur install` and `mur deploy run` fail with `E-REG-006` when a GitHub source is rate limited, refused or unreachable. A rate limit tells you to set `GITHUB_TOKEN`. Scripts matching `E-REG-001` or `E-IO-003` for these failures must also match `E-REG-006`. ([#186](https://github.com/murmur-nexus/murmur/pull/186))
- Breaking: `mur watch` exits `1` with `E-IO-003` when its connection ends without a `capsule-closed` frame, including after `mur stop`. Scripts that expect exit `0` must accept `1`. The stream format is documented on the new Streaming Protocol reference page. ([#184](https://github.com/murmur-nexus/murmur/pull/184))
- Breaking: `mur watch` prints each tool call's outcome after its name, as in `tool: bash [ok, exit 0, 12ms]`. Update scripts that parse these lines. `artifact` stream frames now carry `tool_call_id`, `is_error`, `duration_ms`, `exit_code` and `truncated`. ([#181](https://github.com/murmur-nexus/murmur/pull/181))
- `mur ps` and agent card probes no longer report busy capsules as `unreachable`. ([#183](https://github.com/murmur-nexus/murmur/pull/183))
