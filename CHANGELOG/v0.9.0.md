# Changelog

## Changes since v0.8.0

### Features

- WASM tools with no `capabilities.filesystem.scope` can open the `host_paths` folders in `~/.murmur/config.yaml`, and the whole host under `mur run --unconfined`, at `murmur-host/` followed by the absolute path. `mur run --explain-scope` lists these folders for each tool. ([#387](https://github.com/murmur-nexus/murmur/pull/387))
- `mur run --unconfined` or `containment: unconfined` in `~/.murmur/config.yaml` runs your own capsule directly on the host, with your `HOME`, environment, filesystem, network and `sudo`. The trace, spend ceilings, turn limit, deadlines and hooks still apply, and delegated children and deployed capsules stay contained. ([#386](https://github.com/murmur-nexus/murmur/pull/386))
- `host_paths` in `~/.murmur/config.yaml` gives scoped and sealed capsules' shell commands and native tools `read` or `read-write` access to chosen host folders, such as `~/.cargo`, without giving up containment. ([#385](https://github.com/murmur-nexus/murmur/pull/385))
- A tool artifact can declare a `provider_tool:` block (`kind: computer`) so a driver offers it as its provider's own computer use tool. Such a capsule must run `sealed` and is refused on a `vision: false` model. Driver safety checks pause the task as input-required until a person replies yes. ([#381](https://github.com/murmur-nexus/murmur/pull/381))
- Under `transport: process`, an image a tool attaches to its result reaches the harness as an MCP image item, so Claude Code can see a screenshot a murmur tool made. The trace lists the attachments. ([#380](https://github.com/murmur-nexus/murmur/pull/380))
- `inference.instruction_files` adds work-folder files such as `AGENTS.md` and `CLAUDE.md` to the system prompt after the manifest's own prompt, on both transports. The trace records what was read, missing or cut. ([#377](https://github.com/murmur-nexus/murmur/pull/377))
- Sub-capsules listed under `capabilities.spawn.workdir_snapshot` start each delegation in a private copy of the parent's work folder, so a reviewer can run the parent's code and tests without changing its files. ([#374](https://github.com/murmur-nexus/murmur/pull/374))
- `mur trace show frm_…` lists every task sent to a formation member, not only member calls. Each `a2a_task_received` record says who let the task in and carries a hash of its message. ([#369](https://github.com/murmur-nexus/murmur/pull/369))

### Bug Fixes

- Under `transport: process`, the stream's `artifact` frame for a tool call murmur ran names its fence in `fenceSource` (for example `tool:bash`) instead of `null`. ([#383](https://github.com/murmur-nexus/murmur/pull/383))
- A component call waiting on the host, such as a driver whose provider never answers, is stopped at `capabilities.limits.deadline_seconds` plus a 2-second grace and recorded as `call_deadline`. Gateway `inference` records carry `gateway_reached_ms` and `upstream_responded_ms`. ([#371](https://github.com/murmur-nexus/murmur/pull/371))
- Under `transport: process`, `on-inference` hooks fire before each tool call with its name and input, as on `transport: http`, so `hook-diff-summary` reports a subscription capsule's file edits. ([#370](https://github.com/murmur-nexus/murmur/pull/370))
- `mur install` records the facts `mur run` needs about each `capabilities.shell.allow` binary, so the first launch after an install is as fast as later ones. `--no-precompile` skips this. ([#362](https://github.com/murmur-nexus/murmur/pull/362))

### Other

- Breaking: `mur run --explain-scope`, `mur doctor` and `session_start` list each route a capsule runs with what confines it, and warn with `W-SEC-034` when a `scoped` or `sealed` class leaves one unconfined. A host that cannot give a capsule its own cgroup is reported as unable to run one. The `--explain-scope --json` schema moves to 2, replacing `mechanism_covers` with `routes`. ([#384](https://github.com/murmur-nexus/murmur/pull/384))
- Breaking: WASM and native tools can return PNG, JPEG, GIF or WebP images through their result's `attachments` list, and A2A messages can carry image parts, within the new `context.images` limits. Every WASM tool, driver and script capsule must be rebuilt against WIT level 3 (`murmur:tool@0.2.0`) or is refused with `E-WIT-LEVEL-001`. ([#379](https://github.com/murmur-nexus/murmur/pull/379))
- Breaking: A native tool receives its entry's `config:` block as `MURMUR_ARTIFACT_CONFIG` and, with `capabilities.state`, a private store under `~/.murmur/state/` named by `MURMUR_STATE_DIR`, so `W-SEC-015` no longer fires. Neither name is taken from the host, so `baseline_env` or `env.allow` entries naming them can be deleted. ([#378](https://github.com/murmur-nexus/murmur/pull/378))
- Breaking: Process drivers can report a harness's subscription windows and suggested next prompt, shown in `session-status`, `mur trace show` and new `quota` and `suggested-prompt` stream frames. A process driver built against `murmur:driver@0.3.0` is refused and must be replaced by one built for `murmur:driver@0.4.0`. ([#376](https://github.com/murmur-nexus/murmur/pull/376))
- Breaking: `mur build` packages a standard Agent Skills folder (`SKILL.md` plus the files it points at) with no `murmur.yaml`. A skill folder holding a symlink, both `SKILL.md` and `skill.md`, or a root `murmur-build.json` is refused with `E-BLD-002`. ([#375](https://github.com/murmur-nexus/murmur/pull/375))
- Breaking: A task ended by the session deadline records `exit_status: "deadline_reached"` on `task_end` instead of `"canceled"`. A background command's `shell_completed` line is written when the agent reads the result, and `mur run --resume` on a copied `trace.jsonl` resumes under the session id inside it. ([#373](https://github.com/murmur-nexus/murmur/pull/373))
- Breaking: Shell commands run in the foreground until they exit, and shell commands and native tools get no CPU limits, unless the manifest sets `lifecycle.shell_grace_secs`, `capabilities.resources.cpu_seconds` or `capabilities.resources.cgroup_cpu_percent`. ([#372](https://github.com/murmur-nexus/murmur/pull/372))
- Breaking: A turn cut off at `inference.max_tokens` ends only that turn. The model is told and the task continues, failing with cause `output_cap` after two empty cut-off turns in a row. The trace records such turns as `decision: "capped"` instead of `"text"`. ([#368](https://github.com/murmur-nexus/murmur/pull/368))
- Breaking: A shell tool result no longer repeats the command. It opens with `Exit code:` and drops empty `Stdout:` or `Stderr:` sections, and background answers name the command by its work id. Clients should take the command from the tool call. ([#363](https://github.com/murmur-nexus/murmur/pull/363))
- Breaking: A script capsule writes `session_start`, a `tool_call` per `murmur:tool-registry/invoke` call and a `session_end` saying how `run` ended. It appears in `mur ps` and the `mur-roost` census with `url: null` in `mur ps --json`. ([#361](https://github.com/murmur-nexus/murmur/pull/361))
- A warm `mur run` reaches its first model request a few milliseconds sooner, most of all with a native tool, because artifact archives unpack faster. ([#367](https://github.com/murmur-nexus/murmur/pull/367))
- On Linux, a warm `mur run` of a capsule with `capabilities.shell.allow`, `spawn.allow` or `install.tool` reaches its first request sooner, because cgroup scope setup runs while artifacts load. ([#366](https://github.com/murmur-nexus/murmur/pull/366))
- An agent capsule with neither `inference.max_session_tokens` nor `spend.machine_tokens_per_day` sends its first request sooner, because the request is measured alongside the call. With either ceiling set, every request is still admitted first. ([#365](https://github.com/murmur-nexus/murmur/pull/365))
- `mur run --capsule <name> --capsule-version <v> --deadline` on an installed script capsule gives a hint naming the capsule instead of asking you to edit a `murmur.yaml`. ([#364](https://github.com/murmur-nexus/murmur/pull/364))
