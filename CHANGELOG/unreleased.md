# Changelog

## Changes since v0.4.0

This release changes what `mur run` exits with. A task that does not complete now exits `1` with `E-RUN-040`, where it printed `status:  ok` and exited `0` ([#206](https://github.com/murmur-nexus/murmur/pull/206)). A capsule with `lifecycle.task_acceptance: queue` and `lifecycle.after_task: exit` now ends as soon as its `--task` task does and never sends the model an empty task ([#204](https://github.com/murmur-nexus/murmur/pull/204)). Both lead the `Breaking:` entries under **Other**, with what to change.

### Features

- A capsule holding a `capabilities.install` grant can call `manage.remove()` to uninstall a skill or tool it pulled at runtime. It is removed from the session and from `murmur.lock`. Anything `murmur.yaml` declares, any `origin: operator` pin, and every hook and driver are refused. ([#228](https://github.com/murmur-nexus/murmur/pull/228))
- Capsule manifests accept `inference.tool_refresh` to choose when an artifact installed during a session joins the tools offered to the model. `compaction`, the default, adds it after the next compaction. `immediate` adds it on the next inference call, at the cost of one prompt-cache miss. ([#226](https://github.com/murmur-nexus/murmur/pull/226))
- Capsules can require an HTTP Bearer token on their A2A door by declaring `network.authentication` in `murmur.yaml`. `mur run` prints the tokens. The agent card advertises the scheme in standard A2A terms and shows the session id, tools and grants only to authenticated callers. `mur run --bind`, `mur doctor --bind` and `mur deploy` warn with `W-SEC-032` when a capsule without it is reachable off loopback. ([#225](https://github.com/murmur-nexus/murmur/pull/225))
- A trusted controller can change a running capsule. A `control:` block in `murmur.yaml` names what may change: `inference.max_tokens`, and the credential names behind an artifact's `gateway.api_key`. `mur control` changes a setting from the next inference call, or injects a secret that is held only in memory and never reaches the trace, the conversation record or the agent. ([#222](https://github.com/murmur-nexus/murmur/pull/222))
- `mur deploy run` compiles the capsule's WASM tools, drivers and hooks on the target host before starting it, so a freshly deployed capsule launches as fast as a warm one. Pass `--no-precompile` to skip it. The new `mur precompile` command compiles any `.mur.zip` for the machine it runs on. ([#219](https://github.com/murmur-nexus/murmur/pull/219))
- On Linux, capsules that declare `capabilities.shell.allow` or `capabilities.spawn.allow`, or carry a native tool, start sooner. Setting up their cgroup scope no longer adds a fixed wait of about 20 ms to every launch. ([#216](https://github.com/murmur-nexus/murmur/pull/216))
- `mur install` compiles each WASM tool, driver and hook it installs, so the first `mur run` loads them instead of compiling them and starts as fast as a warm launch. Run with no arguments, it also compiles artifacts already in the store. Installs take longer: installing six test artifacts went from 96 ms to 2.8 s. Pass `--no-precompile` to skip compiling and keep the old install time. ([#214](https://github.com/murmur-nexus/murmur/pull/214))
- A warm `mur run` no longer re-checksums every compiled WASM artifact in `~/.murmur/compiled` on each launch. Each is verified once and checked again only after its file is changed, replaced or has its permissions changed. ([#212](https://github.com/murmur-nexus/murmur/pull/212))
- A warm `mur run` of a capsule with an `inference` block reaches its first inference request sooner. The token counter is now prepared while artifacts load, which took the Nexus coding capsule from 300 ms to 221 ms on four CPUs. ([#211](https://github.com/murmur-nexus/murmur/pull/211))
- A compiled form in `~/.murmur/compiled` and its checksum file are removed together once neither has been used for 30 days. Temp files left behind by a crashed write are removed after an hour. `mur doctor` describes the directory as `compiled WASM cache, safe to delete`. ([#210](https://github.com/murmur-nexus/murmur/pull/210))
- A warm `mur run` of a capsule with WASM tools or hooks starts faster. It no longer decompresses a tool's or hook's WebAssembly module when its compiled form is already cached. ([#209](https://github.com/murmur-nexus/murmur/pull/209))
- A running capsule's `manage.pull()` of a WASM artifact shares the `~/.murmur/compiled` cache with `mur run`. Pulling a version that an earlier pull or launch already compiled no longer recompiles it. ([#208](https://github.com/murmur-nexus/murmur/pull/208))
- `mur run` keeps compiled WASM artifacts in an owner-only `~/.murmur/compiled` cache that `mur doctor` reports. Every launch after the first skips recompiling them, and the Nexus coding capsule starts about 16 times faster. ([#205](https://github.com/murmur-nexus/murmur/pull/205))

### Bug Fixes

- Hooks that call `run-inference` in a `transport: process` capsule get an error saying the call is not available under that transport. It used to tell them to add an `inference.driver.artifact` the manifest already declared. ([#230](https://github.com/murmur-nexus/murmur/pull/230))
- `transport: process` capsules no longer drop the output of `on-inference` hooks. A hook's artifact arrives on the task's stream as an `artifact` event before `completed`, as it does on `transport: http`. ([#218](https://github.com/murmur-nexus/murmur/pull/218))
- A2A tasks accepted while a capsule runs its task under `lifecycle.after_task: exit` or `task_acceptance: single` no longer vanish when the session ends. They end `rejected` over `tasks/get` and `message/stream`, and `mur trace show` lists them as `task_rejected` lines. A message sent to a session that has stopped taking work is answered `rejected`. ([#217](https://github.com/murmur-nexus/murmur/pull/217))

### Other

- Breaking: When a task does not complete, `mur run` prints its status (`failed`, `max_turns_reached`, `spend_ceiling_reached` or `canceled`) and exits `1` with `E-RUN-040`. It used to print `status:  ok` and exit `0`. `tasks/get` reads `failed` for every such task except a cancelled one, a delegated capsule reports `error` to its parent, and a new `task_failed` trace line records why. Scripts that treated a failed inference call, a spent turn budget, a spend-ceiling stop or a cancelled task as success must handle exit `1`. ([#206](https://github.com/murmur-nexus/murmur/pull/206))
- Breaking: A capsule with `lifecycle.task_acceptance: queue` and `lifecycle.after_task: exit` ends as soon as its `mur run --task` task finishes. It no longer idles 30 seconds and then calls the model with an empty prompt. No capsule sends the model an empty task: a launch that receives no task ends after its idle wait without a model call, and a blank `--task` or A2A message fails its task. A capsule that ran from its system prompt alone must now be given its instruction with `--task`. ([#204](https://github.com/murmur-nexus/murmur/pull/204))
- Breaking: Capsules can declare `inference.alternates` and switch to one while running, with `mur control set inference.driver <name>` or, where `control.agent_settings: [inference.driver]` allows it, through the agent's built-in `switch-driver` tool. A switch takes effect from the next inference call and is recorded in the trace. `switch-driver` is now a reserved name, and a capsule declaring an artifact under it is refused at launch with `E-CAP-013`. Rename the artifact. ([#229](https://github.com/murmur-nexus/murmur/pull/229))
- Breaking: A skill or tool whose `murmur.lock` pin has `origin: runtime` reaches the model marked untrusted. Its tool description opens with `[origin: runtime, trust: untrusted]`, and a skill's text arrives inside an `<untrusted-content source=skill:NAME>` fence. The trace records it in `session_start.runtime_artifacts`, in `origin` and `trust` on `skill_call`, and in a new `artifact_pulled` line. Naming such a pin in `inference.system_prompt_artifact` fails `mur run` with `E-RUN-043` until `mur install <name>@<version>` adopts it. ([#227](https://github.com/murmur-nexus/murmur/pull/227))
- Breaking: A capsule can pull an artifact at runtime through `manage.pull()` only when its manifest declares `capabilities.install`, naming the skills and tools it may install (exact names, `prefix-*` or `*`). A capsule that pulled without one must add the block. A spawned capsule whose install grant is wider than its parent's is refused. ([#224](https://github.com/murmur-nexus/murmur/pull/224))
- Breaking: `murmur.lock` entries record `origin: operator` or `origin: runtime`, with the pulling `session`. An artifact a running capsule fetched through `manage.pull()` can no longer be declared as `runtime: hook`, `runtime: driver` or with `gateway:`. `mur run` refuses it with `E-RUN-043` and `mur doctor` flags it until you run `mur install <name>@<version>` to adopt the pin. Locks written by earlier versions read as all-operator and keep working. ([#223](https://github.com/murmur-nexus/murmur/pull/223))
- Breaking: The agent card at `/.well-known/agent-card.json` is a standard A2A v1.0 AgentCard. The address moves to `supportedInterfaces`. `serves` and the session id, tools, shell, network and planes move under `capabilities.extensions`, and `capabilities.cancellation` is gone. Clients that read the previous card must update; the Agent Card reference has a migration table. A capsule started by `mur` v0.4.0 or earlier still serves the old card, and `mur ps` and `mur stop` list it as unreachable until it ends. ([#221](https://github.com/murmur-nexus/murmur/pull/221))
- Breaking: A streamed task ends with exactly one final `status` frame, sent after its `on-task-end` hooks decide. A task a `reopen-task` hook sends back reports the accepted answer, or `failed` once `lifecycle.max_task_reopens` is spent, and each reopen appears as a non-final `working` frame carrying a `reopen` number. A `request-input` timeout or runtime error no longer ends the stream early or leaves it without a final frame, and `message/stream` closes only on its own task's final frame. Clients that stopped at an earlier final frame, or joined `text` across a reopen, should read the answer from the last frame's `response`. ([#215](https://github.com/murmur-nexus/murmur/pull/215))
- `mur install` and `mur run` verify artifact checksums about three times faster. `murmur.lock` and stored checksums are unchanged. ([#207](https://github.com/murmur-nexus/murmur/pull/207))
