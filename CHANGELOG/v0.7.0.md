# Changelog

## Changes since v0.6.0

### Security

- Updates the bundled `zip` crate to 9.0.4, fixing RUSTSEC-2026-0367 to RUSTSEC-2026-0369 (setuid bits and symbolic links during extraction). `mur` does not call the affected code. `mur search` reads the default index from the latest default-artifacts release instead of failing with a 404. ([#311](https://github.com/murmur-nexus/murmur/pull/311))

### Features

- Each formation member's record in `~/.murmur/running/` names its roster member in `formation_member`. ([#316](https://github.com/murmur-nexus/murmur/pull/316))
- `mur trace list --workdir <dir> --json` lists a work folder's sessions, newest first, with each one's id, records directory, start time and whether it is still running. ([#314](https://github.com/murmur-nexus/murmur/pull/314))

### Bug Fixes

- Claude Code on a subscription no longer fails its first turn on macOS with "Not logged in". `transport: process` harnesses now get the host's `USER` and `LOGNAME`. ([#315](https://github.com/murmur-nexus/murmur/pull/315))
- Shell tools can move files between folders of the work folder on Linux 5.19 and later, so `uv` works. On Linux 6.2 and later they can no longer truncate files outside it. `mur doctor` reports the Landlock ABI in force. ([#300](https://github.com/murmur-nexus/murmur/pull/300))
- A manifest with `lifecycle.queue_depth: 0` is refused with `E-MAN-003` instead of crashing the capsule. Task statuses carry a `timestamp`. ([#296](https://github.com/murmur-nexus/murmur/pull/296))

### Other

- Breaking: Capsules started by an older `mur` show as `skipped:` in `mur ps` and cannot be reached by `mur stop`. Stop them with the `mur` that started them. ([#313](https://github.com/murmur-nexus/murmur/pull/313))
- Breaking: On Linux, where the host enforces it, a capsule's commands can no longer change its trace, logs or eval scores. These move to `~/.murmur/records/`, so older sessions are not listed. Scoring hooks need `capabilities.filesystem.records: true`. `mur` needs a usable `HOME`. ([#312](https://github.com/murmur-nexus/murmur/pull/312))
- Breaking: On Linux, where the host enforces it, a capsule's commands can no longer change files the runtime owns, such as the task, `MURMUR.md` and installed tools. They live in `$MURMUR_RUNTIME_DIR`. `--workdir` no longer gets a `murmur.yaml` copy. ([#310](https://github.com/murmur-nexus/murmur/pull/310))
- Breaking: When `capabilities.install` allows it, agents can pull and remove skills and tools mid-session with the built-in `pull-artifact` and `remove-artifact` tools. Both are reserved names. `capabilities.install` is refused under `transport: process`. ([#309](https://github.com/murmur-nexus/murmur/pull/309))
- Breaking: The runtime no longer follows symbolic links in a capsule's work folder, so a capsule cannot use them to reach files outside it. A run that meets one fails with `E-RUN-050`. Replace such links with the real file or folder. ([#308](https://github.com/murmur-nexus/murmur/pull/308))
- Breaking: A `capabilities.shell.allow` entry that is a path, not a binary name, is refused when the manifest is read. ([#307](https://github.com/murmur-nexus/murmur/pull/307))
- Breaking: On Linux, native tools run under the same confinement as shell commands. Grant what they need in `capabilities`, such as `git` in `capabilities.shell.allow`. A capsule whose only subprocesses are native tools fails with `E-CAP-005` on a host without network namespaces. ([#306](https://github.com/murmur-nexus/murmur/pull/306))
- Breaking: A driver built against another WIT interface version is refused with `E-WIT-LEVEL-001`, which replaces `E-RUN-029`. `mur install` refuses versions this `mur` cannot load and names one that fits. `mur version` prints the WIT level this `mur` serves. ([#305](https://github.com/murmur-nexus/murmur/pull/305))
- Breaking: `mur install` fetches `<scope>/<name>` only from the scope owner's GitHub repository, by exact version, and checks each download's sha256. `murmur.lock` records the owner and refuses a change. `registry.sources` entries take only `repo:` and `token:`. ([#304](https://github.com/murmur-nexus/murmur/pull/304))
- Breaking: `mur search` reads only schema 2 indexes and shows the newest version this `mur` can load. Build one with the new `mur index` command. ([#303](https://github.com/murmur-nexus/murmur/pull/303))
- Breaking: Shell commands in a session share one network namespace, so a server one command starts is reachable from the next. Every process a session started is killed when it ends, even if the runtime is killed. ([#302](https://github.com/murmur-nexus/murmur/pull/302))
- Breaking: Artifacts are named `scope/name`, such as `murmur/tool-editor`. Ones from a `.mur.zip` file or `mur publish` are `local/<name>`. Bare names are refused. Delete `murmur.lock` and run `mur install` again. ([#301](https://github.com/murmur-nexus/murmur/pull/301))
- Breaking: Pin the `mur` release for `mur deploy run` with `deploy.mur_version`. A top-level `mur_version` is refused with `E-MAN-003`, and `mur run` no longer warns about it. ([#299](https://github.com/murmur-nexus/murmur/pull/299))
- Breaking: `mur install` and `mur publish` no longer take `--registry`, and `NEXUS_API_KEY` is ignored. `mur search --registry` is now `--index`. Remove any `registry:` block from `murmur.yaml`. ([#298](https://github.com/murmur-nexus/murmur/pull/298))
- Breaking: `SendMessage` waits until the task finishes or asks for input, as A2A v1.0 specifies. Set `configuration.returnImmediately` to get the task back at once. ([#297](https://github.com/murmur-nexus/murmur/pull/297))
- Breaking: Capsule doors serve `ListTasks` and `SubscribeToTask`. A declared credential now reaches only the tasks it started. The push-notification config methods are answered `-32003`. ([#294](https://github.com/murmur-nexus/murmur/pull/294))
- Breaking: The door's own methods are now `murmur.WatchSession` and `murmur.StopSession`. Send `forgetSession` in the message `metadata` instead of the `x-murmur-forget-session` header. `mur watch` and `mur stop` work as before. ([#293](https://github.com/murmur-nexus/murmur/pull/293))
- Breaking: `SendStreamingMessage` streams A2A v1.0 events, so stock A2A clients can read them. Murmur's own frames go only to clients that ask for the murmur stream extension. ([#292](https://github.com/murmur-nexus/murmur/pull/292))
- Breaking: Tasks and messages on a capsule door use A2A v1.0 shapes, such as `TASK_STATE_COMPLETED`. A reply to a task waiting for input must set `taskId`. File parts are refused with `-32005`. ([#291](https://github.com/murmur-nexus/murmur/pull/291))
- Breaking: Capsule doors speak A2A v1.0 only. Requests must send `A2A-Version: 1.0`. Use the v1.0 method names, such as `SendMessage`, in clients and in `network.authentication` scopes. ([#290](https://github.com/murmur-nexus/murmur/pull/290))
