# Changelog

## Changes since v0.11.0

### Features

- The tool a capsule names in `code_mode.repl` can import the `murmur:bus` interface (WIT level 8). Its program lists the capsule's tools and calls them singly or as a batch, under the same grants and hooks as the model's calls. Any other artifact importing `murmur:bus` is refused with `E-CAP-022`. ([#423](https://github.com/murmur-nexus/murmur/pull/423))
- A `code_mode` block in `murmur.yaml` turns on code mode. The named WASM tool keeps one instance and its state for the whole session. A call that runs past `code_mode.detach_after_secs` returns a work id for `background-command`. ([#422](https://github.com/murmur-nexus/murmur/pull/422))

### Bug Fixes

- `mur run` no longer hangs on Linux hosts that pipe core dumps to a crash reporter such as apport or systemd-coredump. A crash in a program started by a capsule's shell command ends the command at once. Its memory is not handed to the reporter. ([#421](https://github.com/murmur-nexus/murmur/pull/421))

### Other

- Breaking: A WASM tool waiting on a `murmur:process` session process reads all of its output, and `read` reports `stdout-ended` and `stderr-ended`. The interface moves to `murmur:process@0.2.0` (WIT level 7). Tools built against `0.1.0`, including `tool-git`, `tool-browser` and `tool-computer`, are refused until rebuilt. ([#419](https://github.com/murmur-nexus/murmur/pull/419))
