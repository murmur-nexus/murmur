# Changelog

## Changes since v0.9.0

### Features

- WASM tools can run allowlisted programs and keep named programs running for the session through the new `murmur:process` interface at WIT level 4. They follow the same `capabilities.shell.allow`, containment, resource limits and `on-shell` hooks as a shell command. ([#390](https://github.com/murmur-nexus/murmur/pull/390))
- `mur install` accepts several artifact references in one command and compiles their WASM artifacts in parallel. When one fails, it still installs the rest, then exits 1 naming every failed reference. ([#389](https://github.com/murmur-nexus/murmur/pull/389))

### Other

- Breaking: Tools are WASM components only. `mur build`, `mur publish`, `mur install` and `mur run` refuse `implementation: native` or `execution: native` and lock entries with per-platform hashes. Rebuild native tools as WASM. ([#394](https://github.com/murmur-nexus/murmur/pull/394))
- Breaking: On Linux kernel tiers, commands run in the session's own PID namespace, and `scoped` and `sealed` commands see a private `/proc`. A container whose seccomp profile refuses `CLONE_NEWPID` is refused with `E-CAP-005`. ([#393](https://github.com/murmur-nexus/murmur/pull/393))
- Breaking: `mur install` refuses with `E-REG-005` a source that serves different bytes for a version `murmur.lock` pins. A version changed in `murmur.yaml` updates its lock entry, and `mur install --frozen` keeps the old refusal for CI. ([#392](https://github.com/murmur-nexus/murmur/pull/392))
- Breaking: `mur run --capsule` reads a relative `system_prompt_file` or local `source:` from inside the installed package. A package built without that file must list it under `requires_files:` and be rebuilt. ([#391](https://github.com/murmur-nexus/murmur/pull/391))
